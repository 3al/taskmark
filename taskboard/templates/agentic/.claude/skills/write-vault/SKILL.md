Создать или обновить заметку в Knowledge Vault (`vault/`).

Волт — внешняя память проекта: знания, добытые в одной задаче, переиспользуются
в следующих, вместо того чтобы каждый раз заново вычитываться из кода.

**Папка `vault/` игнорируется git.** Обычный поиск по проекту её **не видит**:
glob/grep пропускают игнорируемые файлы. Работают только явные пути (`ls vault/*/`,
чтение файла по пути) и поиск с отключённым ignore-фильтром:
`rg --no-ignore "<слово>" vault/`.

## Шаг 1. Определить тему и тип

Если аргумент передан — использовать как тему заметки.

Иначе — определить тему из контекста текущей задачи/разговора.

Определить:
- **domain** — папка в волте: раздел предметной области проекта
- **note-type** — `business`, `code` или `system` (или оба — парные заметки)

## Шаг 2. Проверить существующие заметки

Перед созданием — проверить, нет ли уже заметки на эту тему:
1. Прочитать `vault/SYS/taxonomy.md` — убедиться, что теги каноничные
2. Перечислить файлы в `vault/<domain>/` (явным путём) и открыть подходящие по теме
3. Если заметка существует — обновить её (перейти к Шагу 4)

## Шаг 3. Создать новую заметку

1. Определить домен и создать папку `vault/<domain>/`, если её нет
2. Использовать шаблон `vault/SYS/templates/business-note.md` или `code-note.md`
3. Заполнить фронтматтер:
   ```yaml
   title: Человекочитаемое название
   created: YYYY-MM-DD
   updated: YYYY-MM-DD
   tags: [tag1, tag2]           # из taxonomy.md
   domain: имя-домена
   note-type: business | code | system
   impl: "[[code-note]]"        # для business
   concept: "[[business-note]]" # для code
   ```
4. Заполнить содержание по шаблону

### Правила содержания

**business-заметка:**
- Суть (что это, зачем) — 1-2 абзаца
- Бизнес-правила — ограничения, допустимые значения
- Связи с другими сущностями

**code-заметка:**
- Поток данных — откуда → куда
- Ключевые файлы — пути, методы
- Паттерн — на что похоже, как устроено

## Шаг 4. Обновить существующую заметку

1. Прочитать текущее содержание
2. Добавить/обновить релевантную информацию
3. Обновить `updated: YYYY-MM-DD`
4. Не удалять существующий контент — только дополнять и актуализировать

## Шаг 5. Связать парные заметки

Для новой бизнес-фичи/эндпоинта пара **обязательна** — создавай обе заметки, а не одну:

- **business** (`<verb>-<domain>.md`) — что, зачем, бизнес-правила: семантика полей,
  ограничения, коды ошибок. Frontmatter: `impl: "[[<code-note>]]"`
- **code** (`api-<...>.md`) — файлы, поток данных, паттерны, разбор «почему так».
  Frontmatter: `concept: "[[<business-note>]]"`

В code-заметке фичи `concept:` указывает **только** на свою парную business-заметку —
не на общий `README` домена.

## Шаг 6. Сообщить результат

Выведи краткое резюме:
```
✓ Заметка создана/обновлена: vault/<domain>/<name>.md
  Тип: business | code | system
  Теги: [tag1, tag2]
```

## Важно

- Теги только из `vault/SYS/taxonomy.md` — нужен новый, сначала добавь в таксономию
- Не более 5 тегов на заметку
- Имя файла уникальное в рамках всего волта, `kebab-case` латиницей
- Не дублировать: если знание уже описано — обновить существующую заметку
- Обновлять `updated` при каждом изменении
