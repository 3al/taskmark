# taskboard

Веб-фронтенд (канбан) для менеджера задач на Markdown-файлах (`tasks/`).
Один сервер на несколько проектов, живая очередь, drag-and-drop,
развёртывание структуры задач и агентского окружения (скиллы, правила) в пару кликов.

Стек: Python (FastAPI + uvicorn + watchdog) + React/Vite/Tailwind (собранный фронтенд в репозитории — Node.js не нужен).

## Требования

- Python 3.10+ (`py` на Windows, `python3` на macOS/Linux)
- Всё остальное ставится автоматически при первом запуске (fastapi, uvicorn, watchdog — в `taskboard/.venv`)

## Быстрый старт

1. Получить код: `git clone` или скачать ZIP (Code → Download ZIP) и распаковать.
2. Запустить из любого места:
   ```
   py taskboard.py          (Windows)
   python3 taskboard.py     (macOS/Linux)
   ```
   При первом запуске спросит подтверждение установки зависимостей (флаг `--yes` — не спрашивать).
   Откроется браузер на `http://127.0.0.1:8765`.
3. В шапке: **«+ проект»** → путь к **корню** проекта (папка `tasks/` берётся внутри него).
4. Если структуры нет — кнопка **«Развернуть структуру»**: создаст `board.md`,
   `create_task.py`, `epics.md`, `logs/`, а опционально — скиллы Claude Code,
   команды opencode и секцию правил TASK MANAGEMENT в `AGENTS.md` / `CLAUDE.md`.
5. Пользуйтесь: доска, очередь, создание задач, логи.

Запуск из папки конкретного проекта автоматически добавляет его в реестр
(если сервер уже работает — второй инстанс не стартует, а регистрирует проект).

## Возможности

- **Канбан** по статусам проекта — набор колонок настраивается (см. «Жизненный цикл задач»)
- **Живая очередь** — приоритетные задачи сверху вниз
- **DnD**: карточки между приёмом и очередью (тумблер «по всей доске»), колонки (порядок per-project)
- **Создание задач** из UI: в подраздел бэклога или сразу в очередь (в начало/конец),
  с необязательным эпиком — известные ключи подсказываются, новый попадает в `tasks/epics.md`
- **Мультипроектность**: реестр проектов, переключение в шапке, путь проекта с копированием
- **Scaffold**: развёртывание структуры `tasks/` + агентское окружение
  (скиллы `.claude/skills/`, команды `.opencode/commands/`, правила в AGENTS/CLAUDE,
  поддержка Knowledge Vault — опционально)
- **Валидация** структуры: баннеры проблем, точечное восстановление кнопкой «Создать»,
  обновление устаревших скриптов, скиллов, команд и правил кнопкой «Обновить»
- **Вьюер логов** `tasks/logs/`
- **Настройки** из UI: порт, DnD, имена артефактов (с миграциями при переименовании),
  жизненный цикл задач, остановка/перезапуск сервера

## Жизненный цикл задач

Набор статусов у каждого проекта свой: где-то нет ревью, где-то нужен отдельный статус
ожидания стенда или релиза. Он настраивается в **Настройки (⚙) → Жизненный цикл задачи**
и хранится в конфиге проекта — `tasks/.taskboard.json` (внутри `tasks/`, которая
игнорируется git, поэтому настройки не попадают в репозиторий).

### Как собрать свой пайплайн

Статусы берутся из готового набора: `backlog`, `todo`, `queued`, `to_fix`, `development`,
`local_testing`, `review`, `to_testing`, `testing`, `ready_to_deploy`, `completed`, `done`,
`cancelled`. В редакторе можно включать нужные, убирать лишние и менять порядок стрелками.

**Порядок в списке — это маршрут задачи.** Что правее текущего статуса — «вперёд», что левее —
«назад». Отсюда берутся колонки доски и подсказки скиллов.

Четыре действия говорят, куда скиллы ведут задачу:

| Действие | Что означает | Кто использует |
|---|---|---|
| Новая задача | куда попадает созданная задача | `create_task.py`, кнопка «+» в UI |
| Брать работу из | раздел живой очереди | `start-task` |
| Взять в работу | рабочий статус | `start-task` |
| Вернуть после замечаний | куда возвращают с проверки | `fix-task` |

Пример конфига для флоу с ревью, стендом и релизом:

```json
{
  "pipeline": ["backlog", "todo", "to_fix", "development",
               "review", "to_testing", "testing", "ready_to_deploy", "done", "cancelled"],
  "actions": { "create": "backlog", "pick": "todo",
               "start": "development", "return": "to_fix" }
}
```

Свой статус, которого нет в наборе, тоже можно завести — достаточно описать оформление:

```json
"statuses": { "hotfix_wait": { "label": "Ждёт окна", "section": "Hotfix Wait", "color": "rose" } }
```

### Правила движения

Запретов нет: пайплайн описывает **ожидаемый** маршрут, а не забор. Простую задачу можно
двинуть из разработки сразу в тестирование, а ночной хотфикс — сразу в завершённые.
Ближайший следующий статус скиллы и UI предлагают первым, остальные доступны без церемоний.
Мягкое ограничение остаётся только для мыши на доске (чтобы карточка не уехала случайным
движением) и снимается тумблером «DnD по всей доске».

Два статуса ведут себя особо:

- **`cancelled`** — вне маршрута: перевести в него можно из любого статуса, но как
  «следующий шаг» он не предлагается никогда
- **`to_fix`** — статус возврата, поэтому стоит левее разработки: попадание в него из
  тестирования читается как движение назад, а «вперёд» из тестирования ведёт к релизу

### Что происходит при изменении пайплайна

- включили статус — раздел появляется в `board.md` на своём месте по порядку;
- выключили пустой — раздел убирается;
- выключили статус с задачами — UI спросит, куда их перенести, и подвинет и строки доски,
  и `status:` во frontmatter файлов задач;
- секция правил в `AGENTS.md` / `CLAUDE.md` пересобирается под новый маршрут.

### Смена статуса вручную и агентами

```sh
py tasks/set_status.py TASK-004 development --agent "Имя (модель)"
py tasks/set_status.py --list              # пайплайн проекта
py tasks/set_status.py --targets TASK-004  # куда можно двинуть задачу
```

Скрипт правит `status:` в файле задачи и строку в `board.md` за один вызов — руками
их лучше не разводить. Скиллы (`start-task`, `fix-task`, `finalize-task`) имён статусов
не содержат: они спрашивают их у скрипта, поэтому подстраиваются под пайплайн проекта сами.

## Управление сервером

- Запуск: `py taskboard.py` (флаг `--dev` — авто-перезагрузка при правках backend)
- Остановка/перезапуск: Настройки (⚙) → раздел «Сервер»
- Порт по умолчанию 8765 (меняется в настройках или `--port N`)

## Структура репозитория

```
taskboard.py            # bootstrap + запуск (единая команда)
taskboard/
  backend/              # FastAPI: парсеры доски, DnD-операции, scaffold, watcher (SSE)
  frontend/             # исходники React (для разработки; нужен Node.js)
  frontend/dist/        # собранный фронтенд (закоммичен — Node не нужен)
  templates/            # шаблоны scaffold: tasks/ и агентское окружение
  requirements.txt
```

## Разработка

```
py taskboard.py --dev          # авто-перезагрузка backend при правках
cd taskboard/frontend
npm install && npm run build   # пересборка фронтенда (dist коммитится)

# тесты (stdlib unittest, из корня репозитория)
taskboard/.venv/Scripts/python.exe -m unittest discover -s taskboard/tests -t taskboard -v
```
