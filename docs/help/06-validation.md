# Баннеры проблем

Доска постоянно сверяет структуру проекта с ожидаемой и говорит о расхождениях
прямо над колонками. Молчаливых пробелов нет: если чего-то не хватает, это видно,
и рядом стоит кнопка, которая это чинит.

## Красный баннер — критично

Работать с доской нельзя, пока проблема не устранена: не найдена папка `tasks/`,
нет файла доски, доска не разбирается, в ней нет раздела приёма новых задач.
Крайние случаи («структуры нет вовсе», «нет файла доски») доска показывает не
баннером, а экраном с кнопкой **«Развернуть структуру»**.

Если раздел доски пропал после правки `board.md` руками — верните его заголовок
(`## Backlog` и т. п.) или разверните структуру заново: развёртывание дописывает
недостающее, не трогая существующее.

## Жёлтый баннер — деградация

Инструмент работает, но часть возможностей отключена. Каждая строка чинится
своей кнопкой:

| Проблема | Кнопка | Что делает |
|---|---|---|
| Нет `create_task.py` | Создать | разворачивает скрипт, возвращает кнопку «+ Задача» |
| Нет `set_status.py` | Создать | разворачивает инструмент смены статуса для агента |
| Нет `epics.md` | Создать | заводит реестр эпиков |
| Нет `_TEMPLATE.md` | Создать | возвращает эталон структуры задачи |
| `_TEMPLATE.md` устарел | Подробности | окно расхождений: причина, diff и выбор исхода |
| Нет папки логов | Создать | создаёт `tasks/logs/`, включает кнопку «Логи» |
| Нет разделов доски для статусов маршрута | Создать разделы | добавляет недостающие разделы на их места по порядку маршрута: без раздела у статуса нет колонки, и задача в нём не видна |
| Скрипт устарел | Подробности | там же: обновить, слить с вашими правками или оставить свою версию |
| Скиллы / команды не развёрнуты | Развернуть | доставляет окружение выбранных сред |
| Правила не развёрнуты | Развернуть | добавляет секцию правил в `CLAUDE.md` / `AGENTS.md` |
| Скиллы, команды, правила или файлы волта разошлись с шаблоном | Подробности | открывает окно с diff по каждому файлу |
| Не выбраны среды агентов | Настроить | спрашивает, в каких средах вы работаете |
| Волт знаний не развёрнут | Развернуть | создаёт `vault/SYS` и скилл `write-vault` |
| Требования этапов объявлены, а `set_status.py` про них не знает | Обновить | обновляет развёрнутый скрипт: до этого проверки объявлены, но не работают |

Кнопка **«Подробности»** ведёт в окно расхождений: у каждого файла названа
причина (отстал от шаблона / правки в проекте встретились с новым шаблоном) и
предложен исход — обновить, слить, взять шаблон или оставить свою версию.
Разбор состояний и кнопок — в разделе «Агентское окружение», «Правленные скиллы
и слияние». Правленный вами файл, пока шаблон не менялся, в этот список
не попадает вовсе.

## Синий баннер — нет раздела очереди

В `board.md` отсутствует раздел статуса, из которого берут работу. Кнопка
**«Создать раздел»** добавляет его на своё место по порядку пайплайна.

## Предупреждения

Мягкие расхождения данных, ничего не отключающие:

- задача есть на доске, а файла нет — битая ссылка в строке;
- запись не похожа на свой файл — строка скопирована с чужой доски, id совпал случайно;
- ссылка в строке указывает на старое имя — файл переименовали, строку забыли;
- заголовок в строке не совпадает с файлом — задачу переименовали или строка чужая;
- файл `TASK-*.md` есть, а на доске его нет — задача потеряется из виду;
- раздел строки не совпадает со статусом в файле — правили один конец, забыли второй;
- разделы доски вне пайплайна — колонки не будет, пока статус не включён в маршрут;
- **требование этапа объявлено с ошибкой** — неизвестная проверка, статус вне
  маршрута, одно имя у двух требований, проверка без параметра (например «секция
  непуста» без заголовка секции). Такое требование не сработает, и агент пройдёт
  этап молча: сказать об этом может только доска;
- **в задаче отмечено требование, которого нет в маршруте** — например его
  переименовали в настройках, а отметка в файле осталась. Выглядит как закрытый
  этап, а не закрывает ничего. Такую запись доска не удаляет: ошибка может быть и
  в настройках, и тогда стёрся бы факт, а не мусор.

### Кнопка «Починить данные»

Часть данных живёт в двух местах: статус — разделом доски и полем `status:` в файле,
блокировка — полями `blocked_by` и `blocks` у обеих задач. Разъехавшиеся концы
чинятся разом. Кнопка на баннере открывает окно со списком правок: **сначала
предпросмотр, потом применение**. Правило одно — **файлы задач считаются источником
правды**: доска может врать (её копируют между проектами, правят руками), а файл
задачи — единственное, что реально существует. Доска подстраивается под файлы:

| Что нашли | Что сделает починка |
|---|---|
| Файл есть, строки на доске нет | добавит строку в раздел, соответствующий `status:` из файла (незнакомый статус → раздел приёма задач) |
| Строка лежит не в том разделе | перенесёт её в раздел статуса из файла — сам файл не тронет |
| Ссылка в строке указывает на переименованный файл | перепишет ссылку на актуальное имя, место строки не тронет |
| Заголовок в строке не совпадает с файлом | перепишет заголовок строки из frontmatter — ссылку и место не тронет |
| Строке не соответствует никакой файл | перенесёт её в технический раздел `## Потерянные` |
| Запись чужая: id совпал с вашим файлом, но задача другая | тоже в `## Потерянные` — ваш файл останется как есть и получит свою строку |
| Блокировка записана с одной стороны | проставит вторую сторону: `blocked_by` — авторское поле, `blocks` собирается из него |
| `blocks` указывает на задачу, которая себя заблокированной не считает | уберёт эту ссылку — обратная сторона производная и подстраивается |

**Битые ссылки на несуществующие задачи и циклы кнопка не трогает**: правильного
действия там нет, и они остаются предупреждениями — их разбирают руками
(см. [«Доска, очередь и задачи»](02-board.md)).

Своя строка опознаётся не по одному номеру `TASK-NNN`: номер мог совпасть
со строкой, скопированной с чужой доски. Строка считается своей, если
ссылается на файл точным именем или повторяет его заголовок. Но и точная
ссылка не спасает чужой заголовок: файл — правда, и строка повторит его
заголовок.

Ничего не удаляется. Записи без файла не пропадают, а собираются в разделе
`Потерянные` внизу `board.md` — колонкой он не показывается. Если файл вернётся
(например, подтянули из чужой ветки), следующая починка вернёт задачу из этого
раздела на её место.

Остальные предупреждения чинятся правкой файлов или настройкой жизненного цикла —
см. [«Жизненный цикл задач»](04-lifecycle.md).
