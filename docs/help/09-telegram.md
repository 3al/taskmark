# Задачи из чата Telegram

Сообщение в чате Telegram становится задачей на доске. Taskmark читает чат через
бота, которого вы заводите сами, и заводит задачу у того, кого в сообщении
тегнули.

Сообщение выглядит так:

```
#задача Обновить документацию по API @ivanov
```

Бот отвечает реплаем: `TASK-042 · Обновить документацию по API → бэклог проекта «Мой проект»`.

## Срок задачи

Добавьте один хэштег `#срок` с датой или относительным сроком:

```
#задача Обновить документацию @ivanov #срок 2026-09-12
#задача Обновить документацию @ivanov #срок 3 недели
```

Принимаются дата `ГГГГ-ММ-ДД` и целое неотрицательное число с единицей:
`день`, `дня`, `дней`; `неделя`, `недели`, `недель`; `месяц`, `месяца`,
`месяцев`. Сокращения (`5д`), часы, «завтра» и `12.09` не поддерживаются.
Неверный срок или повторный `#срок` — отказ с подсказкой, задача не создаётся.
Дата в прошлом также отклоняется. Можно указать сегодняшний день или дату позже.

Относительный срок отсчитывается от локальной даты компьютера при обработке
сообщения. `0 дней` — сегодня. Месяцы сохраняют число дня, а если такого числа
нет — берут последний день месяца: 31 января + 1 месяц = 28 февраля
(29 в високосный год). В файле сохраняется рассчитанная дата.

Хэштег и значение срока вырезаются из текста задачи. Остальной текст
сохраняется; слова «до пятницы» без `#срок` остаются обычным текстом.
Без `#срок` задача создаётся как прежде, без срока.

Если бот просит обновить окружение, примените обновление скрипта создания
задач через баннер Taskmark и повторите сообщение: старый скрипт срока
не принимает, поэтому задача с ним не создаётся.

## Как включить

Настройки → вкладка **Telegram**. Возможность выключена по умолчанию и включается
галочкой; пока она выключена, Taskmark в сеть за сообщениями не ходит.

Дальше три шага.

**1. Завести бота.** Напишите в телеграме боту **@BotFather** команду `/newbot` и
ответьте на два вопроса — название и ник (ник должен кончаться на `bot`). В ответ
придёт токен: длинная строка вида `8123456789:AAH…`. Вставьте её в поле и нажмите
«Проверить» — Taskmark покажет имя вашего бота. Под токеном есть поле прокси: оно
нужно, только если телеграм недоступен напрямую (см. «Если телеграм недоступен»).

**2. Разрешить боту видеть чат.** У @BotFather: `/mybots` → ваш бот → *Bot
Settings* → *Group Privacy* → **выключить**. Без этого бот видит только
сообщения, адресованные лично ему. Затем добавьте бота в рабочий чат как
обычного участника.

**3. Связать чат с проектом.** Бот узнаёт о чате, когда в нём пишут: отправьте в
нужный чат любое сообщение, и он появится в списке на вкладке сам. Рядом с именем
чата выберите проект, куда складывать задачи. Искать идентификатор чата не нужно.

Если из одного чата нужно писать в несколько проектов, отметьте остальные в
строке «и по суффиксу» под выбранным.

Там же укажите **свой ник** в телеграме: по нему бот отличает адресованное вам от
чужого.

## Если телеграм недоступен

Заполните поле прокси под токеном на вкладке **Telegram**. Через него пойдут все
обращения бота, включая кнопку «Проверить». Пустое поле означает прямое
соединение.

Адрес пишется одной строкой:

- `http://хост:порт` и `https://хост:порт` — обычный HTTP-прокси;
- `socks5://хост:порт` — имя `api.telegram.org` разрешает ваш компьютер;
- `socks5h://хост:порт` — имя разрешает сам прокси.

Логин и пароль указываются в адресе: `socks5://имя:пароль@хост:1080`. Порт можно
не писать — подставится 1080 для `socks5` и `socks5h`, 80 и 443 для `http` и
`https`.

У `http://` соединение с самим прокси не шифруется — так работает этот вид
прокси. У `https://` Taskmark шифрует и его: логин с паролем не уходят открытым
текстом.

**Прокси для приложения телеграма (MTProto) не подходит.** Бот ходит не по
протоколу MTProto, а по обычному HTTPS, поэтому ссылки вида `tg://proxy?…` здесь
не работают — нужен HTTP- или SOCKS5-прокси.

Второе поле — **свой адрес Bot API**. Оно для другого случая: у вас есть свой
домен, за которым стоит реверс-прокси к `api.telegram.org` (или собственный
`telegram-bot-api`). Тогда впишите туда `https://ваш.домен`, и бот пойдёт по
нему вместо `api.telegram.org`. Прокси при этом не нужен — это отдельный путь, а
не дополнение к нему. Пустое поле означает обычный адрес телеграма.

Ошибка в адресе видна сразу: нажмите «Проверить», и Taskmark скажет, что не так.

**«Сертификат api.telegram.org не прошёл проверку» означает, что прокси читает
ваш трафик.** Такой прокси не пропускает соединение насквозь, а расшифровывает
его у себя и подставляет свой сертификат — вместе с содержимым запросов ему
виден и токен бота. Taskmark в этом случае не отправляет ничего. Так ведут себя
бесплатные публичные прокси; берите тот, которому доверяете.

## Что важно знать

- **Бот у каждого свой.** Один и тот же токен нельзя опрашивать с нескольких
  машин — участники будут перехватывать сообщения друг у друга. Каждый заводит
  своего бота и добавляет его в тот же чат.
- **Доски у всех локальные.** Если тегнули двоих, у каждого появится своя задача
  со своим номером — общей задачи на всех не существует.
- **Бот видит чат только с момента добавления.** Сообщения, написанные раньше, он
  не получит никогда.
- **Нет ответа — значит задача не доехала.** Бот живёт внутри запущенного
  Taskmark: если его не запускали, отвечать некому. Повторите сообщение, когда
  Taskmark будет запущен. Невычитанные сообщения телеграм хранит около суток —
  дольше они не ждут, поэтому Taskmark стоит держать запущенным. В настройках,
  в разделе «Общие», есть галочка **«Запускать при входе в систему»**.
- **Задачи из чата попадают в рубрику «Из Telegram»** — в начале бэклога, а если
  рубрик на доске нет вовсе, она заводится в его конце. У задач из чата нет ни
  типа, ни критериев приёмки: в сообщении их никто не называл, и проставляет их
  тот, кто берёт задачу в работу.
- **Автором задачи становится тот, кто написал сообщение** — его ник, а если
  ника у человека нет, отображаемое имя. Автор виден в открытой задаче (см.
  [«Структура tasks/»](03-structure.md)).

## Уведомления о движении задачи

Когда задача, заведённая из чата, попадает в нужный статус, бот пишет об этом в
тот же чат: номер, заголовок, «было → стало» и теги — ваш и того, кто задачу
принёс.

**О каких статусах уведомлять, вы выбираете сами.** Настройки → «Жизненный цикл»
→ кнопка **«в чат»** у нужных этапов маршрута. Пока вы её не трогали, отмечен
последний этап маршрута — то есть бот пишет только о завершении. Сняли все
отметки — не пишет ни о чём.

Отметить можно и отмену — «задачу отменили» тому, кто её принёс, обычно нужнее
всего. По умолчанию она не отмечена.

Кнопка появляется только при включённой интеграции с телеграмом.

Уведомления касаются **только задач, заведённых из чата**: заведённые в окне
доски и агентом вы и так видите там, где работаете. Бот молчит и тогда, когда не
настроен ни один чат.

Статус можно менять как угодно — мышью на доске, скриптом, руками в файле:
уведомление уходит одинаково, потому что бот смотрит на саму доску, а не на то,
кто её изменил. Сообщение приходит в течение нескольких секунд.

## Напоминание о сроке

Когда до срока задачи остаётся немного, бот пишет в тот же чат: номер,
заголовок, сколько осталось и сама дата, а следом теги — ваш и того, кто задачу
принёс.

**За сколько дней предупреждать, вы выбираете сами.** Настройки → вкладка
**«Telegram»** → «Напоминать о сроке за столько дней»: три поля, по умолчанию
`7`, `3` и `1`. Ненужную границу **очистите** — она перестанет существовать;
очищены все три, значит напоминаний нет вовсе. Отдельного переключателя у
напоминаний нет: пустое поле и есть отказ от границы.

**Сколько раз напомнят, определяет сама задача.** Бот пишет, когда задача
проходит очередную границу, — и проходит она только те, до которых дожила:

- срок через две недели: напоминания за неделю, за три дня и накануне;
- срок завтра: только «накануне» — границы «за неделю» и «за три дня» такая
  задача не пересекала, и говорить по ним не о чем.

**На одной границе напоминание одно.** Бот не повторяет его на каждой проверке.
Если срок перенести, напоминания придут заново — это уже другое обещание.
Отметка о посланном переживает перезапуск.

**В день заведения бот молчит.** Задачу, которую вы только что принесли в чат,
напоминать вам незачем, даже если её срок уже внутри ближайшей границы: первое
напоминание придёт со следующего дня.

Напоминания не приходят по задачам, которые доехали до конца маршрута или были
отменены: срок у них ничего не значит, хотя дата в задаче и остаётся. Уже
просроченные задачи здесь тоже молчат — про них бот пишет отдельно.

Как и уведомления о движении, напоминания касаются **только задач, заведённых
из чата**. Проверка идёт раз в час, пока Taskmark запущен: у выключенного
инструмента таймеров не бывает, и напоминаний он не шлёт.

## Как разбирается сообщение

- **Хэштег** может стоять где угодно: `#задача сделать X @ivanov` и
  `@ivanov глянь #задача сделать X` работают одинаково.
- **Заголовок** — первое предложение или первая строка, смотря что кончится
  раньше. Остальное уходит в описание задачи.
- **Тег исполнителя** — кому задача. Тегнули не вас — ваш Taskmark промолчит.
- **Тегать нужно одного.** Задача заводится на одного человека: если в сообщении
  тегнуто несколько, бот отвечает отказом и задачу не создаёт — на каждого нужно
  отдельное сообщение. Отказ приходит всем тегнутым.

```
#задача Обновить документацию по API. Начать с раздела про фильтры @ivanov
```

даёт задачу «Обновить документацию по API» с описанием «Начать с раздела про
фильтры».

## Если проектов несколько

Обычно чат привязан к одному проекту, и в сообщении ничего указывать не надо.
Когда из одного чата нужно писать в разные проекты, имя добавляется к хэштегу:

```
#задача-Бэкенд Пересчитать индексы @ivanov
```

Выбрать так можно **только среди проектов, привязанных к этому чату**: право
писать в проект даёт привязка в настройках, а не наличие проекта на вашей машине.
Имя вне списка бот не примет и ответит перечнем доступных. Основной проект
называть суффиксом можно — задача уйдёт туда же, куда и без него.

---

> **Граничный случай: Taskmark на двух машинах.** Одного бота на обе завести
> нельзя — очередь сообщений у бота одна, и каждое достанется той машине,
> которая успела опросить его первой. Заводите по боту на машину и разводите их
> по **разным чатам**: чат и есть адрес, по которому задача находит нужную
> доску. Один общий чат на две машины сейчас не настраивается: обе машины видят
> в сообщении ваш ник и заведут задачу каждая у себя.
