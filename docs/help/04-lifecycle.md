# Жизненный цикл задач

Набор статусов настраивается для каждого проекта: **Настройки (⚙) → Жизненный
цикл**. Хранится в `tasks/.taskboard.json`.

**«Взять готовый маршрут»** подставляет в форму жизненный цикл целиком: из
встроенного пресета (простой, с ревью, полный, с релизами) или из другого
проекта. Применяется кнопкой «Сохранить».

## Как собрать пайплайн

Статусы выбираются из набора: `backlog`, `todo`, `queued`, `to_fix`,
`development`, `local_testing`, `review`, `to_testing`, `testing`,
`ready_for_release`, `release_notes`, `to_release`, `ready_to_deploy`,
`completed`, `done`, `cancelled`. Лишние выключаются, порядок меняется
стрелками.

**Порядок — это маршрут задачи**: правее — вперёд, левее — назад. По нему
строятся колонки доски и подсказки агенту.

- **Выпуск версий** — статусы `ready_for_release` → `release_notes` →
  `to_release`, пресет «С релизами». Подробнее — [«Выпуск версий»](08-release.md).
- **Выкатка на стенд** — `ready_to_deploy`.

Действия говорят агенту, куда вести задачу:

| Действие | Что означает | Кто использует |
|---|---|---|
| Новая задача | куда попадает созданная задача | `create_task.py`, кнопка «+ Задача» |
| Брать работу из | раздел живой очереди | `start-task` |
| Взять в работу | рабочий статус | `start-task` |
| Вернуть после замечаний | куда возвращают с проверки | `fix-task` |
| Ревью задач | этап разбора кода | подсказка следующего шага |
| Готовить заметки релиза | куда попадает отобранное в выпуск | `release` |
| Отобрано в релиз | состав с утверждёнными текстами | `release` |

Первые четыре нужны всем, остальные — только при таком этапе (иначе «не
используется»). Статусы из набора подставляются в действия сами; свой статус
ревью или выпуска назначьте в действии вручную.

**Тип задачи и маршрут.** Задачи типов «Обсуждение» и «Код-ревью» агент не ведёт
через ревью и выпуск: после проверки он предлагает закрытие. Этапы он узнаёт по
действиям из таблицы.

Свой статус, которого нет в наборе, описывается в конфиге:

```json
"statuses": { "hotfix_wait": { "label": "Ждёт окна", "section": "Hotfix Wait", "color": "rose" } }
```

## Правила движения

- Задачу можно двигать в любой статус, вперёд и назад; первым предлагается
  ближайший следующий.
- `cancelled` доступен из любого статуса, но следующим шагом не предлагается.
- `to_fix` стоит левее разработки: переход в него — движение назад.
- **Настройки (⚙) → Жизненный цикл → «DnD по всей доске»** ограничивает
  перетаскивание мышью (см. [«Доска, очередь и задачи»](02-board.md)).

Если у этапа есть требования, агент не уведёт задачу дальше, пока они не
выполнены. Вы переносите карточки свободно — доска только предупредит о долге.

## Исполнитель на этапе

Кнопка **«исполнитель»** у статуса отмечает этап, на котором нужно назвать, кто
занимается задачей (обычно ревью и тестирование). По умолчанию не отмечен ни
один.

- В открытой задаче появляется метка исполнителя.
- Агент не переведёт задачу на такой этап без имени и спросит вас.
- Доска переносит без имени, но на карточке будет долг «исполнитель назначен».
- На неотмеченном этапе назначить исполнителя нельзя; снять можно везде.

## Требования этапа

Кнопка `✓` у статуса раскрывает список того, что нужно выполнить, **чтобы уйти с
этапа**.

- **Рекомендации** отмечены точкой: агент получает напоминание, но этап проходит.
- **«Сделать обязательным»** превращает рекомендацию в условие выхода.
- **Своё требование** добавляется формой ниже:

| Проверка | Что смотрит |
|---|---|
| подтверждение человека | вы подтвердили в диалоге переноса или сказали агенту |
| секция есть в файле задачи | заголовок секции на месте |
| секция непуста | в секции есть хотя бы одна строка |
| поле задачи заполнено | например `epic` или ссылка на MR |

- У требования есть служебное имя (`verified`, `commits`), оно записывается в
  файл задачи. Имя должно быть уникальным — занятое редактор не примет.
- Перед сохранением доска покажет задачи, которые уже прошли этап и получат долг,
  и спросит, включать ли требование.

**Что стоит требовать:** то, что можно выполнить к моменту выхода с этапа, и то,
что есть кому закрыть. Требование, которое закрывает агент, при ручных переносах
останется долгом на карточке.

### Кого требование не касается

Подпись **«все типы»** / **«кроме: …»** у требования открывает выбор типов задач,
для которых оно не действует. То же — строкой «Не касается задач» при создании.
У задач исключённых типов требование не спрашивается.

Если в Taskmark появился новый тип задачи, баннер назовёт требования, которые его
не учитывают:

- **«Дописать»** — добавит тип в исключения рекомендаций из поставки;
- **«Настроить»** — для ваших собственных требований: решаете вы, вопрос задаётся
  один раз.

## Изменение пайплайна

- Включили статус — в `board.md` появится раздел.
- Выключили пустой — раздел удалится.
- Требования выключенного статуса удаляются вместе с ним.
- Выключили статус с задачами — доска спросит, куда их перенести.
- Секция правил в `CLAUDE.md` / `AGENTS.md` пересоберётся под новый маршрут.

## Команды set_status.py

> Это инструмент агента: вы двигаете задачи на доске или просите агента (см.
> [«С чего начать»](01-start.md)).

```sh
# py — Windows; без лаунчера py — python; macOS/Linux — python3
py tasks/set_status.py TASK-004 development --agent "Имя (модель)"
python tasks/set_status.py TASK-004 development --agent "Имя (модель)"
py tasks/set_status.py --list                     # пайплайн проекта
py tasks/set_status.py TASK-004 --targets         # куда можно двинуть задачу
py tasks/set_status.py TASK-004 --debt            # долг по требованиям
py tasks/set_status.py --queue                    # очередь сейчас (--limit 0 — вся)
py tasks/set_status.py TASK-004 --position 2      # 2-е место в своём разделе
py tasks/set_status.py TASK-004 --after TASK-002  # сразу за TASK-002
py tasks/set_status.py --changelog                # тексты утверждённого выпуска
py tasks/set_status.py TASK-004 --note "суть" --agent "Имя (модель)"
```

- Смена статуса правит и `status:`, и `board.md`.
- `--position` и `--after` без статуса переставляют задачу внутри раздела, не
  меняя статус и дату. Со сменой статуса `--position` принимает только `start` и
  `end`.
- `--changelog` выводит тексты «Изменение для пользователя»: пустая строка —
  сказать нечего, `null` — секции нет. Другой статус — `--changelog <статус>`.

## Подсказки при смене статуса

`set_status.py` печатает напоминания `[!]` в двух точках:

- **задача уходит из работы на проверку** — сохранить знание в волт (если он
  включён);
- **работа по задаче закончена** — в статусе перед подготовкой текстов релиза
  или, если такого нет, в последнем статусе:

```
[!] незакрытых пунктов плана: 2 — «Написать тест», «Обновить справку»
[!] секция «История коммитов» пуста: по строке на коммит задачи …
[!] задачу ждут: TASK-039 — их пометки снимают у них: --unblock TASK-041
```

У обсуждений и код-ревью о пустой «Истории коммитов» не напоминается.
Подсказки переход не блокируют.
