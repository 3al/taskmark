# Структура tasks/

Всё, чем живёт доска, лежит в папке `tasks/` вашего проекта:

```
tasks/
  board.md            # доска: разделы-статусы и строки задач
  TASK-001-*.md       # файлы задач
  epics.md            # реестр эпиков: ключ → имя
  create_task.py      # создание задачи (номер, файл, строка на доске)
  set_status.py       # смена статуса (frontmatter + board.md за один вызов)
  logs/               # логи работы (показываются кнопкой «Логи»)
  .taskboard.json     # настройки проекта: жизненный цикл, имена артефактов
  .gitignore          # папка не попадает в репозиторий проекта
```

Имена не зашиты: `board.md`, `create_task.py`, папку логов и раздел очереди можно
переименовать в **Настройках (⚙)** — доска мигрирует данные вслед за переименованием.

## board.md

Доска — источник правды о том, где какая задача. Разделы `##` — статусы (колонки),
подразделы `###` внутри — группы (например, «Новый функционал», «Баги»), строки —
задачи:

```markdown
## To Do

- TASK-042 · [Поиск по доске](TASK-042-поиск-по-доске.md) · Claude Opus 5 · 2026-07-28
```

В строке: номер, ссылка на файл задачи, кто последним менял статус и когда.

## Файл задачи

```markdown
---
id: TASK-042
title: Поиск по доске
epic: ~
status: todo
created: 2026-07-28
patch: ~
---

## Описание
## Чеклист
## Заметки агента
## История коммитов
```

Статус хранится в двух местах — `status:` во frontmatter и раздел `board.md`.
Разводить их руками не нужно: перетаскивание на доске и `set_status.py` правят оба.

## epics.md

Эпик — Jira-подобный ключ (`E056-18500`), объединяющий несколько задач. Имя эпика
хранится только в `epics.md`; в задаче стоит лишь ключ в поле `epic:`. Задачи одного
эпика ищутся по ключу:

```sh
grep "epic: E056-18500" tasks/TASK-*.md
```

## Настройки проекта

`tasks/.taskboard.json` — жизненный цикл статусов, имена артефактов, выбранные среды
агентов. Файл лежит внутри `tasks/`, потому что папка игнорируется git: настройки не
засоряют репозиторий проекта, но переезжают вместе с ним.

Скрипты `tasks/*.py` автономны — они читают этот конфиг сами, рядом с собой, и
работают без запущенного сервера доски.
