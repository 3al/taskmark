# Структура tasks/

```
tasks/
  board.md            # доска: разделы-статусы и строки задач
  TASK-001-*.md       # файлы задач
  _TEMPLATE.md        # шаблон новой задачи
  epics.md            # реестр эпиков: ключ → имя
  create_task.py      # создание задачи
  set_status.py       # смена статуса и полей задачи
  notify.py           # уведомление на доску от агента
  logs/               # логи (кнопка «Логи»)
  handoff.md          # буфер перехода в новую сессию (есть, пока не прочитан)
  .taskboard.json     # настройки проекта
  .taskboard/         # служебное: копия развёрнутого окружения и резервные копии
  .gitignore          # папка не попадает в репозиторий
```

Имена этих файлов одинаковы во всех проектах. Скиллы и правила для агентов лежат
вне `tasks/` — см. [«Агентское окружение и среды»](05-agentic.md).

## board.md

Разделы `##` — статусы (колонки), подразделы `###` — группы, строки — задачи:

```markdown
## To Do

- TASK-042 · [Поиск по доске](TASK-042-поиск-по-доске.md) · Claude Opus 5 · 2026-07-28
```

В строке: номер, ссылка на файл, кто последним менял статус и когда.

- Подразделы бэклога — типы задач («Баги», «Обсуждения» и т. д.); новая задача
  ложится в подраздел своего типа, а если его нет — в конец раздела.
- Раздел `## Потерянные` — служебный: туда [починка данных](06-validation.md)
  складывает строки без файла задачи. Колонкой он не показывается.

## Файл задачи

```markdown
---
id: TASK-042
title: Поиск по доске
epic: ~
type: feature
size: ~
due: ~
status: todo
created: 2026-07-28 14:00
author: доска
origin: ~
blocked_by: ~
blocks: ~
paused: ~
---

## Описание            ← что и зачем, внутри «### Критерии приёмки»
## Комментарии         ← хронология работы
## История коммитов    ← коммиты по задаче
```

- Разделы новой задачи задаёт `tasks/_TEMPLATE.md`. Правите шаблон — меняются
  новые задачи; кнопка «Обновить» на баннере вернёт его к исходному виду.
- Заголовки разделов не переименовывайте и не переставляйте; «История коммитов» —
  последняя. Если структура нарушена, `set_status.py` предупредит строкой `[!]`.
- Абзацы разделяйте пустой строкой, перечисления пишите списком.
- Комментарии вида `<!-- ... -->` на доске не показываются и не копируются.
- Статус хранится и в `status:`, и разделом `board.md`; доска и `set_status.py`
  правят оба.

### Комментарии

Каждый комментарий — отдельная строка списка с датой, временем, автором и сутью:

```markdown
- **2026-07-28 14:32** · Claude Opus 5 · причина бага в парсере доски
```

Агент добавляет их командой `set_status.py TASK-NNN --note "суть" --agent
"модель"`, вы — кнопкой «+ комментарий». Строка встаёт в конец раздела.

Смена статуса и другие действия записываются сами:

```markdown
- **2026-07-28 15:04** · доска · Development → Testing
- **2026-07-28 18:20** · скрипт (Claude Opus 5) · Testing → Ready for Release
- **2026-07-29 10:12** · доска · блокировка: ждёт TASK-013
- **2026-07-30 09:40** · скрипт (Claude Opus 5) · тип: bug (было feature)
```

Подпись — кто сделал: `доска` — вы мышью, `скрипт (модель)` — агент,
`скрипт вручную (модель)` — агент в обход скилла, с причиной отдельной строкой.
Строки переходов в окне задачи выделены цветами статусов.

## Поля задачи

> Команды `set_status.py` здесь и ниже — для агента. Вы меняете поля в открытой
> задаче на доске или просите агента (см. [«С чего начать»](01-start.md)).

| Поле | Что это | Как поменять |
|---|---|---|
| `id`, `title` | номер и название | название — карандашом в открытой задаче |
| `status` | статус, совпадает с разделом `board.md` | перенос на доске, `set_status.py TASK-NNN <статус>` |
| `created` | дата и время создания | ставится само |
| `type` | вид работы: `feature`, `bug`, `refactor`, `cleanup`, `discussion`, `design`, `review` | метка в открытой задаче, `--type` |
| `size` | объём: `S`, `M`, `L`, `XL` | метка в открытой задаче, `--size` |
| `due` | срок, только дата | метка в открытой задаче, `--due` |
| `epic` | ключ эпика | открытая задача |
| `assignee` | кто занимается задачей сейчас; появляется при назначении | метка в открытой задаче, `--assignee` |
| `author` | кто принёс задачу | ставится само |
| `origin` | чат, из которого пришла задача | служебное, ставится само |
| `blocked_by` | задачи, которые эта ждёт | открытая задача, `--block` / `--unblock` |
| `blocks` | задачи, которые ждут эту; обратная сторона `blocked_by` | ставится само |
| `paused` | причина паузы | открытая задача, `--pause` / `--resume` |
| `cancel_reason` | причина отмены; появляется при отмене | вопрос доски, `--reason` |
| `confirmed` | подтверждённые требования этапов (`verified, release_ok`) | диалог переноса, `--confirm` |

`~` и пустое значение означают «нет». Команды —
`set_status.py TASK-NNN --<поле> <значение>`; пустое значение снимает поле.
Задача без типа, размера, срока или исполнителя — норма.

Требование этапа «поле задачи заполнено» проверяет поле, которое вы назвали в
настройках (например, ссылку на MR). Такое поле записывает во frontmatter агент
или вы в файле задачи.

**Тип** задаёт метку на доске, подраздел бэклога и следующий шаг маршрута (см.
[«Жизненный цикл задач»](04-lifecycle.md)). Список — `set_status.py --types`.

**Размер** ставит агент, когда берёт задачу в работу. Значения поясняет
`set_status.py --sizes`.

**Срок** принимает дату или относительное значение:

```sh
set_status.py TASK-NNN --due 2026-09-12
set_status.py TASK-NNN --due "3 недели"
```

- Единицы — дни, недели, месяцы; число целое; `0 дней` — сегодня.
- Отсчёт от сегодняшней даты; если в месяце нет нужного числа — последний день
  месяца.
- Каждый перенос срока записывается в «Комментарии».
- На карточке срок показывается словами; просроченный — красным, ближайшая
  неделя — жёлтым. У завершённых и отменённых задач предупреждений нет.

**Исполнитель** спрашивается только на этапах с галочкой «исполнитель» (см.
[«Жизненный цикл задач»](04-lifecycle.md)). Список имён общий для всех проектов;
агенту его отдаёт `set_status.py --assignees`.

**Автор** ставится при создании: `доска`, ник отправителя из Telegram или имя
модели агента.

## Срезы задач

```sh
set_status.py --epic E056-18500          # задачи эпика
set_status.py --by author "@nick"        # по любому полю
set_status.py --by assignee "Иванов"
set_status.py --due-slice                # сроки на неделю вперёд (--due-slice 30 — месяц)
```

Задачи выводятся в порядке маршрута. На доске то же показывает клик по эпику,
автору или исполнителю в открытой задаче.

## epics.md

Реестр эпиков: ключ (`E056-18500`) и имя. В задаче хранится только ключ в поле
`epic:`.

## Настройки

- **Проекта** — `tasks/.taskboard.json`: жизненный цикл, выбранные среды и прочие
  настройки проекта. Скрипты `tasks/*.py` читают его сами и работают без
  запущенной доски.
- **Инструмента** — `~/.taskboard/config.json`: порт, тема, проверка обновлений и
  другие общие настройки. Там хранятся только изменённые вами значения; пустой
  файл `{}` — норма. Рядом `projects.json` — список проектов.
