# Выпуск версий

Раздел для тех, кто выпускает свой проект версиями. Как обновлять сам Taskmark —
в [«Обновления и версия»](07-updates.md).

## Статусы выпуска

| Статус | Что означает |
|---|---|
| **Ready for Release** | проверено, ждёт выпуска |
| **Release Notes** | отобрано в выпуск, пишется текст для пользователей |
| **To Release** | текст утверждён, задача едет в выпуск |

Готовый маршрут — пресет **«С релизами»** в **Настройки (⚙) → Жизненный цикл**.
В своём маршруте назначьте статусам действия **«Готовить заметки релиза»** и
**«Отобрано в релиз»**.

## Как проходит выпуск

Скажите агенту **«готовь релиз»**:

1. Агент показывает три колонки выпуска и спрашивает, что взять из «Ready for
   Release».
2. Переносит отобранное в «Release Notes» и пишет черновики в секцию «Изменение
   для пользователя».
3. Показывает черновики — вы правите их или убираете задачи.
4. Переносит утверждённое в «To Release» и собирает changelog.
5. Предлагает разряд версии и после подтверждения выпускает.

За вами — состав, тексты и разряд версии.

- Задачи, перенесённые в «Release Notes» или «To Release» мышью, скилл учитывает
  наравне с отобранными.
- Задачу в «To Release» без текста скилл назовёт и предложит написать текст.
- Текст правится в открытой задаче карандашом у секции «Изменение для
  пользователя».
- **Пустая секция** — сказать пользователю нечего, задача в changelog не попадёт.
- Одинаковые тексты разных задач объединяются в одну строку.

## Свой скрипт выпуска

Без скрипта агент готовит состав, тексты и changelog и останавливается —
выпускаете вы. Со скриптом агент вызывает его и закрывает задачи после успеха.

Путь к скрипту внутри проекта — **Настройки (⚙) → Выпуск → «Скрипт выпуска
версии»** или ключ в `tasks/.taskboard.json`:

```json
{ "release_script": "tools/release.py" }
```

### Контракт скрипта

Аргументы на входе, JSON на выходе.

**Проверка** — ничего не меняет:

```
<скрипт> --check --bump minor
```

```json
{ "ok": true, "current": "1.0.0", "next": "1.1.0", "blockers": [] }
```

`blockers` — причины, по которым выпускать нельзя; агент покажет их все.

**Выпуск:**

```
<скрипт> --apply --bump minor --notes путь/к/файлу --tasks TASK-001,TASK-002
```

```json
{ "ok": true, "version": "1.1.0", "tag": "v1.1.0" }
```

`--notes` — файл UTF-8 с телом секции changelog без заголовка версии. `--tasks` —
состав выпуска.

**Публикация:**

```
<скрипт> --publish
```

```json
{ "ok": true, "pushed": true, "release": { "ok": false, "reason": "…" } }
```

Ошибку шагов после публикации (например, записи о релизе на хостинге) верните в
`release` — выпуск при этом считается состоявшимся.

**Отказ** — ненулевой код возврата и `{"ok": false, "error": "..."}`. Агент покажет
ошибку и остановится.
